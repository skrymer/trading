# Regime read-out v3 (trend-efficiency) is pre-registered as a frozen Choppiness overlay that demotes inefficient GRIND spells to CHOP — descriptive-only, v2 untouched

The frozen-and-live v2 classifier (ADR 0024) cannot separate **GRIND** (a quiet, *efficient* up-drift) from **CHOP** (a low-efficiency whipsaw): v2's only directional-quality input is `volLow` (≤12% annualized 20-bar realized vol) plus a ±2% dead-band on one 20-bar SPY return — an *amplitude* channel with no notion of **path efficiency**, so both labels are Grade D (descriptive-only, ungateable). v3's first detection track (issue #180; parent epic #168) adds the missing channel — a **multi-week SPY trend-efficiency axis** — as a **clean-new pre-registration** (never a v2 tweak; the no-v3-by-iteration discipline of ADR 0024), **strategy-blind**, and **descriptive-only**. It produces a *report characterization*, not a strategy gate.

This ADR is the **pre-registration freeze**: every parameter below is fixed by a stated rule and **frozen on 2026-06-16, before any v3 coverage was computed**. It was signed off as text by the quant-analyst before any code (expert-review-precedes-persistence, the ADR 0023 pattern). It does **not** supersede ADR 0023/0024 — v2 remains the production read-out under those ADRs; a supersession of 0024 would be a separate future decision at the #168 integration cutover (below).

## The decision: v3 is a *post-process overlay on v2's published stream*, not a new decision table

The efficiency axis may only affect the GRIND↔CHOP split — the CRISIS/THRUST/NARROW backbone must stay **byte-identical**. Adding an efficiency conjunct at v2's *raw-label* stage would violate that: in `publish()`, GRIND/CHOP raw labels dwell against each other, and a CRISIS/THRUST/NARROW *published* spell only ends once a background label reaches `dwellDays` consecutive raw days — so demoting even one raw GRIND day would shift a preceding backbone label's published **end-date**. So v3 runs the **entire frozen v2 pipeline unchanged** and post-processes its *published* output:

```
P2(t)             = v2 published label   (RegimeReadoutParams.FROZEN pipeline — byte-identical, copied not recomputed)
trendEfficient(t) = choppiness30(t) != null && choppiness30(t) <= 38.2     // null / indeterminate band ⇒ false (fail-closed)

for each maximal run R of consecutive days with P2(t) == GRIND:
    keep GRIND   if  count{t in R : trendEfficient(t)} / |R|  > 0.50         // strict majority
    else relabel every day in R to CHOP                                      // ties (= 0.50) demote
days with P2(t) in {CRISIS, THRUST, NARROW, CHOP, null}: copied verbatim
```

Consequences of the overlay form, asserted as invariants: **`v3-GRIND ⊆ v2-GRIND`** (efficiency only ever removes whole GRIND spells; never promotes), the backbone is byte-identical by construction (copied), and **label stability is inherited** from v2 (spell boundaries are preserved, so median-spell and flips/yr cannot regress). Rejected alternative: a per-day-with-dwell demotion (more powerful, but reintroduces flicker and forfeits the trivial byte-identical proof). Rejected framing: a "positive `CHOP = up-tape AND inefficient`" rule — that is two names for one residual bucket; CHOP stays the honest residual of ADR 0024, now additionally fed the demoted inefficient-GRIND spells.

## The frozen signal spec (rule-fixed, pre-compute)

- **Axis — Choppiness Index, window N = 30 trading days.** Rule: the midpoint of the research-cited 20–60-day multi-week band, one window, fixed before compute, never swept. The literature-standard N=14 (≈3 weeks) is explicitly **ruled out** as below the multi-week floor at which daily efficiency stops being white noise. Registered as a new constant `efficiencyWindowBars = 30` — *not* reused from the backbone's `lookbackBars = 20` (the axis stays decoupled).
  ```
  CI(t) = 100 · log10( Σ_{i=t-29..t} TR_i / ( max High_{t-29..t} − min Low_{t-29..t} ) ) / log10(30)
  TR_i  = max( High_i − Low_i ,  |High_i − Close_{i-1}| ,  |Low_i − Close_{i-1}| )   ; first bar (no prior close) = High − Low
  ```
  Computed on the **adjusted** `(high, low, closePrice)` — all three on the same split+dividend-adjusted basis (Midgaard harmonizes stored High/Low to the adjusted close, so the "adjusted-close + raw-High/Low" mismatch trap does not apply), **not** `rawClose` (the ADR 0027 absolute-level leg, nullable, wrong basis here).
- **Thresholds — literature-fixed 38.2 / 61.8.** `CI ≤ 38.2 → efficient` (GRIND-eligible); `CI ≥ 61.8 → choppy`; `38.2 < CI < 61.8 → indeterminate` (no efficiency claim). Indeterminate **and** null both count as **not** `trendEfficient` (fail-closed). Caveat recorded: applying the 38.2/61.8 bands at N=30 (vs their usual N=14 provenance) relies on the index's `log10(N)` window-normalization holding the band meaning roughly invariant — there are still **zero fitted cutoffs** (we never tune them), but the band-at-N=30 validity rests on that normalization, not on N=14 calibration.
- **Sign — not inverted.** High Choppiness = little net distance per unit path = inefficient. This is *definitional* for the Choppiness Index (no empirical sign-test needed, unlike Kaufman ER). Corollary that motivates the overlay form: low Choppiness is **direction-blind** (an efficient *decline* is also low-Choppiness), so efficiency can only *filter* the up-tape claim v2's directional legs already make — it can never source a label itself.
- **Bad-print guards (determinism):** `high ≤ 0 || low ≤ 0 || (maxHigh − minLow) ≤ 0` ⇒ `choppiness30 = null` ⇒ not-efficient. SPY will not hit these; pre-registered for determinism.
- **Kaufman Efficiency Ratio ER(30) is computed as an advisory observability field only** (`RegimeAxes.efficiencyRatio30`), never an input to the rule — so the research's "ER sign must be tested" caveat is moot here.
- **Observability:** `RegimeAxes` gains nullable `choppinessIndex30` + `efficiencyRatio30` (v2 leaves both null). Observability only — never gated beyond the GRIND-demotion overlay.
- **Warmup** is unchanged at `WARMUP_CALENDAR_DAYS = 400`: the 30-bar efficiency window (+1 for the first true range, ≈44 calendar days) seeds well inside the binding 252-bar drawdown leg that already sets 400.

## Acceptance protocol (all pre-registered; computed only after this freeze)

Primary, against the **frozen** anchor spans (GRIND: 2013, 2017, 2019-H1; CHOP: 2011-H1, 2015-H1, 2015-H2→2016-Q1 — never edited to pass):

1. **Anchor coverage** — GRIND and CHOP each ≥ 60% on their spans, with **no regression** of CRISIS (Grade A) or THRUST, and inherited stability (median published-spell ≥ 15 trading days, ≤ 12 flips/yr).
2. **CHOP direction-coherence** — the frozen **D-FLAT ≥ 70%** diagnostic (≥70% of CHOP days have |SPY 20-bar return| < 2%) stays binding and unchanged. A hard "% of CHOP days read ≥ 61.8" criterion was **rejected** — it introduces a free parameter and mis-specifies the residual, which legitimately contains indeterminate-band and efficient-down days. D-FLAT is the only binding CHOP criterion.
3. **Random-walk surrogate** — null = stationary (Politis–Romano) block bootstrap of SPY daily **log** returns, mean block length **L = 5** (one week ≪ the 30-day window: preserves marginals + up-to-weekly vol-clustering, destroys the multi-week trend the axis claims). Statistic `Δ = mean CI30 over CHOP-anchor dates − mean CI30 over GRIND-anchor dates`, on the real series and on each of **K = 1000** surrogate paths (frozen, recorded seed) over the identical anchor calendar windows. Pass: real `Δ > p95` of the surrogate distribution (one-sided, `p = (1 + #{Δ_surr ≥ Δ_real}) / (K+1) < 0.05`). Parametric GBM was **rejected** (i.i.d. Gaussian has no autocorrelation — the axis beats it trivially and meaninglessly).
4. **Frozen-param OOS on the efficiency axis's own stationarity** — freeze all params on data through **2014-12-31** (bisects no anchor span), apply unchanged to 2015–2025, and require no material era divergence in **GRIND-survival-rate** (fraction of v2-GRIND spells kept GRIND) and the **surviving-GRIND-vs-demoted-CHOP mean-Choppiness ordering**. A spell-*stability* OOS test was reframed out — it is trivially inherited from v2 (the overlay adds zero fitted params), so it is uninformative; the inherited stability floors serve only as a secondary check on the final stream.

**Report-only diagnostics** (observability, never pass/fail): the **GRIND-demotion rate** (fraction of v2-GRIND spells relabeled CHOP) and the per-spell Choppiness-band histogram for GRIND vs CHOP spells. A near-zero demotion rate is a recordable **"axis inert" negative result**; a meaningful rate *with* GRIND coverage holding ≥ 60% and D-FLAT ≥ 70% is the axis adding information.

## One-shot, no-sweep (the classifier-level ARS firewall)

Because GRIND/CHOP are non-gateable, they are never validated against held-out strategy P&L — so this pre-registered freeze plus the surrogate and OOS tests are the **only** anti-snooping protection, and the discipline is therefore *stricter* than v2's §5 revision loop. N=30, 38.2/61.8, and the >0.50 majority are frozen here, before compute. **A failed anchor is a recorded negative result, never a retry at another N or threshold.** Only a structural correction with a stated non-coverage rationale (e.g. a discovered data defect) is legal pre-compute. The v2 GRIND/CHOP anchor spans are reused only as a *one-shot* acceptance check of rule-fixed params; the surrogate (3) and frozen-OOS (4) tests are the uncontaminated-ground-truth supplements ADR 0024 demands.

## Scope, promotion, and lifecycle

- **Descriptive-only; promotes nothing.** `RegimeLabelCondition.GATEABLE_LABELS` stays **CRISIS + THRUST**; the GRIND/NARROW/CHOP conditions still reject at build time. v3 passing does **not** auto-promote GRIND/CHOP to gateable — promotion is a *separate* future pre-registration, contingent on all four acceptance checks passing.
- **No engine/report wiring in #180.** v3 adds no `loadReadoutMapIfGated`, no new conditions, no backtest-engine coupling. The series is exposed solely via `GET /api/regime/readout?...&version=V3` (default `V2`, case-insensitive) for the validation harnesses; `/current`, `/decomposition`, `/sector-matrix` stay on v2. The live strategy-assessment report keeps reading v2 until the #168 cutover.
- **The demoted published stream is non-causal by design.** Because a GRIND spell is demoted on its *whole* spell's efficiency, the published label on the spell's first day depends on later days of the same spell — the stream is retrospective, not as-of. This is sound for a descriptive read-out and its anchor/surrogate/OOS validation (which score the classification, not a live signal), but it is a second, independent reason v3 must not feed anything that consumes the label *as of an entry date* (the per-trade decomposition, regime gating) — the #168 cutover must first convert the overlay to a causal as-of rule. The per-day axis legs (Choppiness, ER, gap, vol, drawdown) are all strictly trailing; only the spell-overlay decision is retrospective.
- **The `version` switch is transitional scaffolding, modeled by a `RegimeReadoutVersion` enum (`V2` default, `V3`).** It exists only while a frozen-and-live classifier must coexist with a candidate under validation. **On resolution it is removed, win or lose** — if the *integrated* v3 (#180 + #181 NARROW + #182 THRUST-recall, re-pre-registered as one joint partition and clearing the 19 anchor spans) is accepted, a future ADR supersedes 0024, v3 becomes production, and `computeReadoutSeriesV3` collapses back to the single production `computeReadoutSeries` (the v2 method + the `version` param deleted); if v3 fails, the v3 path + the `version` param are deleted and v2 remains sole. At most two paths ever coexist: v2 (production) + the single evolving v3 candidate. This cleanup is a committed obligation of this ADR, not optional.
- **Final acceptance is the integrated v3, not this track alone.** #180 builds and validates the trend-efficiency axis (does it separate GRIND/CHOP on the anchors?); the five labels are a joint partition whose whole-classifier acceptance is owned by epic #168.
